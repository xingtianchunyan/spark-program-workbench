# CKB 核心概念（预审技术判断基准）

> 用途：判断提案的技术描述是否准确、是否误解 CKB 基本机制。
> 来源：docs.nervos.org / nervosnetwork/rfcs，蒸馏于 2026-08。

## Cell 模型（CKB 的 UTXO 扩展）

- CKB 的状态单元是 **Cell**，可视为"通用化 UTXO"：每个 Cell 包含 `capacity`（占用的 CKB 数量，1 CKB = 1 字节存储）、`lock script`（所有权/解锁条件）、`type script`（可选，状态转换规则）、`data`（任意数据）。
- **存储即占用**：在链上存数据必须锁定对应数量的 CKB 作为 capacity；数据删除后 CKB 释放。这是"1 CKB ≈ 1 字节"的由来，也是提案中"零成本上链"类说法的常见错误点。
- Cell 是**一次性**的：花费即销毁，同时创建新 Cell。所有状态转换都是"销毁旧 Cell + 创建新 Cell"，由 type script 验证规则。
- **常见误解**：把 Cell 当成以太坊账户模型；认为可以"修改"一个 Cell（实际是销毁重建）；忽略 capacity 租金成本。

## Lock Script 与 Type Script

- **Lock Script**：决定谁能花费这个 Cell（默认 secp256k1 签名；也有 JoyID passkey、多签、Omni Lock 等）。
- **Type Script**：决定 Cell 的状态转换规则（如 sUDT 的发行量守恒、Spore DOB 的铸造规则）。
- 脚本代码以"代码 Cell"形式部署在链上，其他 Cell 通过 `code hash + hash type` 引用。**同一脚本只需部署一次**。
- **关键判例（DevLaunch Kit，2026-07-28 拒绝）**：CKB 的普通转账**不需要部署合约**。提案若声称"为用户转账部署合约"属于基本概念错误，委员会据此怀疑其真实性。

## CKB-VM

- 基于 **RISC-V** 指令集的虚拟机，脚本可用任何能编译到 RISC-V 的语言编写（主流为 Rust，也有 C）。
- 2025-07-01 **Meepo 硬分叉**激活 CKB-VM V2（来源：CKB 生态公开报告，2026-04），带来性能提升与新 syscall。
- 链上脚本开发门槛高于 EVM：无"Solidity 式"高级语言一站体验，测试与调试工具链仍在完善（评审开发工具类提案时的背景）。

## 代币与经济模型基础

- CKB 原生代币用途：支付存储占用（capacity）、矿工手续费、Nervos DAO 质押。
- **二级发行**（每年固定约 13.44 亿 CKB）持续通胀，持有者可存入 Nervos DAO 对冲稀释——DAO 存款的 CKB 处于锁定状态，提案涉及"锁仓生息"时需注意与 Nervos DAO 的区别。
- 交易费极低（通常 < $0.01），但**非零**；提案中"免手续费"通常指 Fiber 通道内或代付方案（如 JoyID/OMIGA 的代付），须追问谁在支付。

## 账户抽象与签名方案现状

- 默认 secp256k1（与比特币相同曲线，地址格式不同）。
- **JoyID**：passkey 钱包（生物识别，无助记词），2026 年用户超 80 万（来源：CKB 生态公开报告，2026-04）。
- **Omni Lock**：支持以太坊/比特币等外部链签名直接操作 CKB 资产的锁脚本。
- 提案做"新钱包/新签名方案"时，必须说明与 JoyID、Omni Lock、Neuron、CKBull 的差异化。

## 跨链现状（安全敏感区）

- **Force Bridge 已于 2025-06 被攻击**（约 $390 万损失），随后停运；2026-01 社区批准 **Rosen Bridge** 作为替代跨链方案（来源：CKB 生态公开报告，2026-04）。
- 涉及跨链桥的提案属高风险区，须重点审查安全假设；优先关注 RGB++/Fiber 这类原生方案而非托管桥。

## 硬分叉时间线（判断"最新"表述的基准）
